# PPT 行为示例

这些是设计示例，不代表已经在真实项目中复现。

## 首次沉淀

用户明确验收季度经营汇报 PPT，并要求沉淀发布。读取最终稿、可访问纠错记录和验收证据。提炼内容结构、数据检查、图表表达、排版和交付要求，将公司名称、指标值、页数和配色参数化。B 中没有合适条目时新增 report-ppt。新提炼原文未在新项目执行，validation 使用 reviewed。只发布通用方法和脱敏变更说明。

## 基于实际版本迭代

项目二实际使用 report-ppt@1.0.0，保存精确来源。多轮纠错发现统计周期和单位不一致造成返工，修正后验收。沉淀时补充制作图表前的数据口径检查和对应验收，保留实际来源；不把本次某个指标变成所有 PPT 的必选内容。

## 远端推进

项目二实际使用 1.0.0，远端已到 1.1.0 并新增可编辑文件交付要求。保留 lineage.source 指向 1.0.0，整合远端与本次改进，integration_base 指向 1.1.0 的实际提交和正文哈希，新版高于 1.1.0。不能判定的冲突保留草稿，只询问关键冲突。

## 无变化或变体

仅替换数据、主题和周期，未发现通用增益时保持原版，不生成空提交。经营汇报转为学术答辩，论证结构、参考文献和验收有实质差异时建立新 ID，记录 variant 来源，保留经营汇报原条目。

## 证据不足

目标仍有关键未完成项时可以生成本地草稿，注明问题，不发布为成功方法。只读到部分聊天时如实说明覆盖范围，不编造其余对话。
